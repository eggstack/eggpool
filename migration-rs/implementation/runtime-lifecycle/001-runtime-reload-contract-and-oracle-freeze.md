# R001 — Runtime/Reload Contract and Deterministic Oracle Freeze

Status: closed; see [closure record](../../closure/runtime-lifecycle/001-status.md)

Source roadmap: `migration-rs/subsystems/runtime-lifecycle-roadmap.md`

Primary class: invariant/infrastructure

Hard dependencies: accepted C011 / M7 closure.

## Objective

Freeze the Python runtime-generation, rehash, task-ownership, retirement, shutdown, and active-state-authority behavior into deterministic fixtures before Rust adds generation publication. R001 is evidence-only except for test/oracle helpers; it must not add a Rust runtime manager or change server behavior.

## Authoritative Python sources

At minimum inspect and encode behavior from:

- `src/eggpool/runtime_manager.py`
- `src/eggpool/generation_factory.py`
- `src/eggpool/config_reload_policy.py`
- `src/eggpool/reload_transaction.py`
- `src/eggpool/runtime_task_inventory.py`
- `src/eggpool/runtime_tasks.py`
- `src/eggpool/reload_diagnostics.py`
- startup/shutdown/reload wiring in `src/eggpool/app.py`
- `src/eggpool/cli_rehash_helper.py` for server-side result semantics only.

## Required fixture corpus

Create a versioned deterministic fixture under `migration-rs/fixtures/runtime-lifecycle/`, generated by a bounded Python oracle helper under `tests/migration_rs/` or `scripts/` following existing migration conventions.

The fixture must include:

### Ownership inventory

For each relevant service/resource classify:

- process-owned;
- generation-owned;
- candidate-owned before publication;
- request/lease-owned;
- retained-finalization-owned;
- startup-only/restart-required.

The corpus must explicitly cover database/repositories, provider client pool, account/catalog/router/coordinator, finalization supervisor, model-router affinity, wire resolver, task supervisor(s), crash reconciler, runtime metrics/reload diagnostics, and server constructor state.

### Generation/candidate lifecycle

Freeze:

- candidate states and legal transitions;
- reverse cleanup order on abort;
- active/retiring/closing/closed/failed-close states;
- lease admission and release semantics;
- publication gate behavior;
- retirement readiness conditions;
- shutdown adoption/drain behavior.

### Reload transaction

Freeze observable state/result vocabulary for:

- identical digest/no-op;
- valid live-only change;
- restart-required change;
- mixed live + restart-required change;
- invalid config;
- expected-digest mismatch/stale caller;
- candidate construction failure;
- preflight/process-transition failure;
- cancellation before acceptance;
- cancellation during/after the acceptance window;
- successful publication with retirement pending vs already drained.

Record changed sections, generation id progression, retirement-pending signal, restart-required paths, and safe error categories. Do not snapshot secret values.

### Config reload policy

Export the complete path -> disposition table (`live`, `restart_required`, `ignored`) plus secret-path/redaction metadata. Include the fail-closed default for unknown paths.

The fixture must be precise enough for R005 to assert every Rust config field is classified. Dynamic maps such as providers/accounts/model routers may be represented by their accepted top-level wildcard/section rule where Python does so.

### Background inventory

Freeze each registered task's:

- name;
- ownership class;
- default enabled state;
- interval/initial-delay/run-immediately/timeout policy;
- reloadable config fields;
- generation/process dependencies;
- callback kind.

Also record the config conditions that enable/disable or reschedule tasks.

### Active-authority observations

Capture which live fields affect request-visible behavior after reload, especially:

- providers/accounts/model routes;
- routing/retry/wire negotiation settings;
- `server.max_request_body_bytes`;
- model exposure/staleness settings used by request/readiness paths;
- transcoder/security finalization policies;
- task intervals/retention settings.

Capture which fields remain constructor-owned and require restart, especially listener/auth/DB/middleware/route-topology fields.

### Retirement/shutdown

Freeze:

- old request continues on old generation while a new request uses the new generation;
- stream lease survives handler return;
- retained finalization prevents premature generation close;
- live retirement does not abandon accepted terminal work;
- shutdown stops new acquisition/publication and eventually closes generations/resources;
- process shutdown can use a tighter forced bound than live rehash retirement.

## Normalization policy

Normalize only nondeterministic identifiers/timestamps into explicit semantic fields. Preserve:

- state names/order;
- booleans;
- changed/restart-required path ordering where user-visible;
- task names/specs;
- generation increments;
- retirement-pending state;
- error class/category distinctions.

Do not normalize away a distinction merely because Rust has not implemented it yet.

## Tests

Add tests proving:

- the fixture is deterministic across two oracle runs;
- every Python reload-policy field exported is unique/classified;
- no secret/API/proxy value is present in fixture JSON;
- task inventory names are unique;
- all expected lifecycle/transaction states are represented;
- fixture schema/version changes fail explicitly rather than silently accepting old projections.

## Scope boundaries

R001 must not:

- add `arc-swap`;
- create Rust generation manager/factory code;
- change Axum state/handlers;
- implement rehash/control socket/CLI;
- add background loops;
- modify DB schema.

## Acceptance criteria

R001 closes only when:

- the complete reload disposition/redaction table is committed;
- ownership, candidate, lease, publication, retirement, shutdown, task, and reload outcomes are represented;
- current live-vs-restart request authority is explicit;
- fixtures are deterministic and secret-free;
- no production behavior changed;
- R002 can implement a generation factory without rediscovering Python ownership ad hoc.
